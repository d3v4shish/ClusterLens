# Architecture

ClusterLens is a local PyQt desktop application. `apps.pyqt_production` builds the shell, owns QSettings/runtime services, and coordinates the Gallery, Clustering, and lazy-loaded Faces workspaces.

Folder selection flows from `SourcePane` to the main window, gallery, and Faces folder review. The selected folder is the tree root; job status is separate from the persistent footer path chip.

Clustering workers discover images, generate embeddings, cache results under the application runtime, and return compact result data to the UI thread. Gallery widgets use paged/model-backed presentation and bounded thumbnail caches.

Faces has two storage boundaries: per-folder review/index data and a global face database mapping face records to image paths. Faces always scans the folder selected in the shared folder pane; it has no competing folder override. Entering the Faces workspace asynchronously primes both boundaries from disk—global album plus selected-folder review—without indexing or rescanning. The primary task selector maps All Faces, Detect, and Find to retained internal pages; Review & Name and identity administration remain implemented but are deliberately hidden from that selector during the redesign. The active detector/embedder pipeline and review filters are selected in a modal editor.

All Faces uses model-backed group lists: Named Photos merges face tiles by their persisted person name, while Grouped Photos displays the raw clustering groups. Its sidebar maintains status internally for result publishing but renders only paged actions with hover and help affordances. The shared dense theme differentiates navigation tabs, subordinate result tabs, fieldset sections, primary actions, and secondary/configuration actions through explicit QSS selectors and `kind` properties. Background result filtering resolves saved metadata for every tile, so raw cluster titles list every current name in the cluster and naming in Detect, selected Grouped Photos tiles, grouped clusters, or another workspace is reflected in all views after the global album, folder review, identities, and result groups refresh. Detected-face and Grouped Photos tiles use standard extended selection: Shift selects a range, Ctrl changes individual membership, and a right-click on an already selected tile preserves that selection. Raw cluster groups also support extended selection for batch naming. Single-face menus contain only single-face actions, while multi-face menus contain only batch-safe naming, clustering, and removal actions. Menus are shown asynchronously, so opening one does not nest a UI event loop. Find by Face embeds a supplied query photo; Find by Name + Similar uses the saved identity prototype embedding and therefore returns named and still-unlabeled similar faces. Its applied settings are stored in QSettings; face model files are either in the managed runtime cache (normally `~/.local/share/ClusterLens/cache/face_model_assets` on Linux) or read directly from a user-selected external folder. Reusable managed download archives are kept beside them in `cache/face_model_downloads`. External files are never copied, moved, or deleted by ClusterLens.

Downloaded models are durable runtime data, not rebuildable caches. Face bundles are staged, checksummed, and published by atomic directory rename; an intent record outside the bundle directory allows startup to promote an interrupted install or restore a missing bundle from a verified local archive without networking. Clustering models share the same runtime cache in the app, worker, and downloader; startup repairs stale Hugging Face `refs/main` pointers to a complete local snapshot. Only the explicit model-cache deletion action removes these assets.

All model download, indexing, cache maintenance, and image decoding work runs through background jobs. The UI thread only renders progress and applies completed results.
